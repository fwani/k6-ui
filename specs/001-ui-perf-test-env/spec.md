# Feature Specification: UI 기반 성능 테스트 환경 구축

**Feature Branch**: `001-ui-perf-test-env`  
**Created**: 2025-03-16  
**Status**: Draft  
**Input**: PRD (docs/prd.md) — UI 기반 성능 테스트 환경 구축, 웹 UI에서 테스트 파라미터 설정·실행, 결과를 대시보드에서 시각화, Docker Compose로 전체 환경 실행 가능

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 테스트 생성 (Priority: P1)

사용자는 웹 UI에서 성능 테스트를 생성할 수 있다. 테스트 대상 URL, HTTP 메서드(GET/POST/PUT/DELETE), 요청 본문(선택), 헤더, 동시 사용자 수, 테스트 지속 시간, 요청 간 대기 시간, 테스트 이름을 입력한다.

**Why this priority**: 테스트가 없으면 실행·결과 조회가 불가능하므로 최우선이다.

**Independent Test**: 테스트 생성 화면에서 파라미터를 입력하고 저장하면, 목록에 해당 테스트가 나타나며 이후 실행 가능하다.

**Acceptance Scenarios**:

1. **Given** 테스트 생성 화면에 접근한 상태, **When** 필수 항목(대상 URL, 메서드, VUs, 지속 시간, 테스트 이름)을 입력하고 저장, **Then** 테스트가 생성되고 목록에 표시된다.
2. **Given** 테스트 생성 화면, **When** POST/PUT 시 요청 Body를 입력하고 저장, **Then** 해당 Body가 테스트 설정에 포함된다.
3. **Given** 테스트 생성 화면, **When** Header를 설정하고 저장, **Then** 설정한 Header가 테스트에 반영된다.

---

### User Story 2 - 테스트 실행 (Priority: P2)

사용자는 생성한 테스트를 UI에서 시작·중지할 수 있고, 실행 상태(Ready / Running / Finished / Failed)를 확인할 수 있다.

**Why this priority**: 생성 다음으로 실행이 있어야 부하 테스트가 수행된다.

**Independent Test**: 테스트 실행 화면에서 "시작" 후 "중지"까지 동작하고, 상태가 Running → Finished 또는 Failed로 전환되는 것을 확인한다.

**Acceptance Scenarios**:

1. **Given** 생성된 테스트가 Ready 상태, **When** 사용자가 실행을 시작, **Then** 상태가 Running으로 바뀌고 부하 테스트가 수행된다.
2. **Given** 테스트가 Running 상태, **When** 사용자가 중지, **Then** 테스트가 종료되고 상태가 Finished 또는 Failed로 갱신된다.
3. **Given** 실행 화면을 보고 있는 상태, **When** 테스트가 실행 중이거나 종료됨, **Then** 현재 상태(Ready/Running/Finished/Failed)가 명확히 표시된다.

---

### User Story 3 - 테스트 결과 조회 (Priority: P3)

사용자는 테스트 결과를 UI에서 확인할 수 있다. 평균·최대 응답 시간, 실패율, 요청 수, TPS/RPS, 테스트 실행 시간이 표시되며, 시각화 대시보드로 이동하는 링크를 통해 상세 메트릭을 볼 수 있다.

**Why this priority**: 결과가 없으면 테스트 실행의 가치가 없어진다.

**Independent Test**: 완료된 테스트의 결과 화면에서 요약 지표가 보이고, 대시보드 링크로 이동해 시각화를 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 테스트가 Finished 상태, **When** 사용자가 결과 화면을 연다, **Then** 평균 응답 시간, 최대 응답 시간, 실패율, 요청 수, TPS/RPS, 실행 시간이 표시된다.
2. **Given** 결과 화면, **When** 사용자가 대시보드 링크를 클릭, **Then** 요청 수/초, 응답 시간, 에러율, 가상 사용자 수, 처리량 등이 시각화된 대시보드 페이지로 이동한다.

---

### User Story 4 - 테스트 히스토리 조회 (Priority: P4)

사용자는 이전에 실행한 테스트 목록을 조회할 수 있다. 테스트 이름, 실행 시간, 상태, 주요 결과 요약을 확인할 수 있다.

**Why this priority**: 히스토리는 비교·추적에 유용하나, 단일 실행만으로도 MVP 가치를 만족한다.

**Independent Test**: 테스트 목록 화면에서 과거 실행 목록이 보이고, 항목별 이름·실행 시간·상태·요약 결과가 표시된다.

**Acceptance Scenarios**:

1. **Given** 하나 이상의 테스트가 실행된 적 있음, **When** 사용자가 테스트 목록 화면을 연다, **Then** 테스트 이름, 실행 시간, 상태, 주요 결과 요약이 목록으로 표시된다.
2. **Given** 테스트 목록 화면, **When** 사용자가 목록 항목을 선택, **Then** 해당 테스트의 상세 결과 또는 실행 화면으로 이동할 수 있다.

---

### Edge Cases

- 사용자가 테스트를 생성할 때 대상 URL이 비어 있거나 잘못된 형식이면, 시스템은 저장 전에 검증하고 오류 메시지를 보여 준다.
- 테스트 실행 중 네트워크 또는 실행 환경 오류로 실패하면, 상태를 Failed로 표시하고 사용자에게 실패 상태를 알린다.
- 동시에 여러 테스트를 실행하려 할 때, 시스템은 한 번에 하나의 테스트만 실행하거나, 동시 실행 정책에 따라 제한·순차 처리한다.
- 대시보드 링크 접근 시 메트릭 저장소에 데이터가 아직 없거나 서비스가 비정상이면, 사용자에게 대시보드 사용 불가 또는 데이터 부재를 안내한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자가 웹 UI에서 테스트 대상 URL, HTTP 메서드(GET/POST/PUT/DELETE), 요청 Body(선택), Header, 동시 사용자 수(VUs), 테스트 지속 시간, 요청 간 대기 시간, 테스트 이름을 설정하여 성능 테스트를 생성할 수 있도록 해야 한다.
- **FR-002**: 시스템은 생성된 테스트에 대해 "시작"과 "중지" 동작을 제공해야 한다.
- **FR-003**: 시스템은 테스트 실행 상태를 Ready, Running, Finished, Failed 중 하나로 표시해야 한다.
- **FR-004**: 시스템은 테스트 종료 후 UI에서 평균 응답 시간, 최대 응답 시간, 실패율, 요청 수, TPS/RPS, 테스트 실행 시간을 표시해야 한다.
- **FR-005**: 시스템은 테스트 결과를 시각화하는 대시보드 페이지로 이동할 수 있는 링크를 UI에 제공해야 하며, 대시보드에는 요청 수/초, 응답 시간, 에러율, 가상 사용자 수, 처리량이 포함되어야 한다.
- **FR-006**: 시스템은 이전에 실행한 테스트 목록을 테스트 이름, 실행 시간, 상태, 주요 결과 요약과 함께 조회할 수 있게 해야 한다.
- **FR-007**: 시스템은 테스트 생성 화면, 테스트 실행 화면, 테스트 결과 화면, 테스트 목록 화면을 제공해야 한다.
- **FR-008**: 전체 테스트 환경(UI, API, 부하 실행 엔진, 메트릭 저장소, 대시보드)은 단일 실행 명령으로 기동 가능해야 한다.
- **FR-009**: 시스템은 테스트 생성 시 대상 URL 등 필수 입력에 대한 검증을 수행하고, 오류 시 사용자에게 명확한 메시지를 보여 주어야 한다.
- **FR-010**: 시스템은 테스트 실행 실패 시 상태를 Failed로 기록하고 사용자가 이를 확인할 수 있게 해야 한다.

### Key Entities

- **성능 테스트(Performance Test)**: 한 번 정의된 테스트 설정. 대상 URL, HTTP 메서드, Body, Header, VUs, 지속 시간, 대기 시간, 테스트 이름 등 속성을 가진다.
- **테스트 실행(Test Run)**: 특정 성능 테스트의 한 번의 실행. 실행 시각, 상태(Ready/Running/Finished/Failed), 그리고 실행 결과와 연결된다.
- **테스트 결과(Test Result)**: 한 테스트 실행에 대한 결과. 평균/최대 응답 시간, 실패율, 요청 수, TPS/RPS, 실행 시간 등 요약 지표와, 대시보드에서 보는 상세 메트릭으로 구성된다.

## Assumptions

- 인증·권한은 MVP 범위 밖이며, 동일 환경 접근자는 동일 권한을 가진다.
- 테스트는 코드 작성 없이 UI 설정만으로 정의·실행되는 방식을 전제로 한다.
- 메트릭 저장 및 대시보드 제공을 위한 별도 서비스(메트릭 저장소·대시보드)가 환경에 포함되며, UI에서 해당 대시보드로 이동하는 링크만 제공하면 된다.
- 동시 실행은 한 번에 하나의 테스트만 실행하는 방식으로 제한해도 된다(필요 시 추후 확장).
- 부하 테스트 실행 엔진과 메트릭 수집·저장은 제품 요구사항에 명시된 도구를 사용한다고 가정하며, 스펙은 "부하 테스트 수행" 및 "대시보드 시각화" 관점으로 기술한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 코드 작성 없이 웹 UI만으로 성능 테스트를 생성할 수 있다.
- **SC-002**: 사용자가 UI에서 테스트를 시작·중지하고 실행 상태를 확인할 수 있다.
- **SC-003**: 부하 테스트가 사용자가 설정한 파라미터(VUs, 지속 시간 등)에 따라 수행된다.
- **SC-004**: 사용자가 UI에서 평균/최대 응답 시간, 실패율, 요청 수, TPS/RPS, 실행 시간을 확인할 수 있다.
- **SC-005**: 사용자가 UI에서 제공하는 링크를 통해 요청 수/초, 응답 시간, 에러율, 가상 사용자 수, 처리량이 시각화된 대시보드에 접근할 수 있다.
- **SC-006**: 전체 테스트 환경을 한 번의 실행 명령으로 기동할 수 있다.
- **SC-007**: 사용자가 이전 실행 목록에서 테스트 이름, 실행 시간, 상태, 주요 결과 요약을 조회할 수 있다.
